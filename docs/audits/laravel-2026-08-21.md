# Laravel audit, 2026-08-21

Produced by the project-local skill `.claude/skills/mikko-laravel-audit/SKILL.md`,
created for this run because the installed `mikko-*` suite has no PHP fingerprint
(its detector reports `language: unknown` on this repo) and no Laravel-specific
audit. The skill is the Laravel analogue of the user-wide .NET audit: a pre-flight
fit check, a deterministic grep pass that gathers candidates before any model
tokens are spent, five parallel read-only judges over non-overlapping scopes, and
a severity-ranked report. Every check pairs a smell with a legitimate
counter-example, most of them drawn from this repository's own documented history.

  `app/`, 14 Blade templates, no untracked PHP)

A zero-finding result deserves suspicion, so the basis is stated plainly: the
candidate pass fired on 121 real sites, and each judge's reply names the specific
code it read and the counter-example each candidate matched, rather than waving
the group through. This codebase has also already absorbed four review passes
(PRs 9, 12, 20, 24) whose fixes are exactly the shapes this audit hunts.

## How each group cleared (Phase 2)

The judges read every candidate with surrounding context and, where a candidate
looked deliberate, checked the decision log before clearing it. The load-bearing
clearances, so a reader can spot-check them:

### A: container, configuration and composition

The one `env(` hit outside `config/` is `app/Console/Commands/DocsCheck.php:511`,
a regex that scans config files for env keys, not a runtime call. There are no
manual container bindings at all, which is the documented design
(`AppServiceProvider::register()` is deliberately empty), so no singleton can
capture the session. The seven `Config::set` sites in
`app/Console/Commands/Snapshot.php` are the save-first, restore-in-finally shape
the skill names as the legitimate counter-example, with the previous values
captured before the try and `DB::purge('snapshot')` tearing down the one additive
key.

### B: Eloquent and database

Every real query site eager-loads what is walked downstream:
`app/Services/ReadLogService.php:358` applies `with('book')` for the three
listing queries, and `app/Services/Ai/LibraryAsk.php:127` loads
`['book', 'embedding']` before ranking. The unbounded library listing at
`app/Services/ReadLogService.php:98` is the documented no-pagination choice
(STATUS.md, known rough edges) and is immune by the calibration rules. All six
mass-assignment seeds are Collection `->all()` calls, not model writes; writes go
through the readonly DTOs. Both raw-SQL sites bind with `?` placeholders,
including the escape character (decision 46). The check-then-act seeds at
`app/Services/ReadLogService.php:76` and `:194` are the confirming re-queries
inside a `UniqueConstraintViolationException` catch running in a savepoint, which
is the documented race recovery, not the race.

### C: outbound HTTP boundary

Every `Http::` call site carries an explicit non-zero timeout, including both
requests inside the search pool (`app/Services/External/OpenLibraryClient.php:47`
and `app/Services/External/GoogleBooksClient.php:38`, both from the 10 s config
default that matches the .NET HttpClient). No response body is consumed without a
`failed()`/`ok()` gate or the settle pattern. Every log line that could embed a
credentialled URL routes through `Redact::apiKey()`
(`app/Services/BookSearchService.php:131`, `app/Services/Ai/OllamaClient.php:72`
and `:162`); the remaining log sites cannot reach the Google key at all. Nothing
touches the network outside the `Http` facade.

### D: web surface

The one real `{!! !!}` in the codebase, `resources/views/book.blade.php:46`,
renders a value the controller sanitised first (invariant S5); the other two hits
are Blade comments. All six GET routes were followed into their controller
actions: reads only, with the reader switch on POST. The embedding backfill a
`GET /library?ask=` can trigger is the write decision 95 documents. No
request-supplied value reaches a redirect; all four sites are named-route
targets. Every query-parameter read is shape-guarded before use: `is_string`
gates in `BookController` and `LibraryController`, `stringOrNull`/`intOrNull` in
`LogController`, so `?q[]=x` and `?ask[]=x` fall through as null rather than
fataling (the decision 29 convention, held everywhere). There are no CSRF
exemptions.

### E: errors, state and lifecycle

Every catch judged either logs with a reason, recovers with a comment naming why,
or is narrowly typed: the degradation catches log before falling back, the
unique-violation catches re-query and rethrow when the race was not the tolerated
one, and the two empty-body catches (`app/Services/Ai/EntryEmbedder.php:131`,
`app/Console/Commands/Snapshot.php:191`) carry the decision-backed comments
(107 and 137). No broad catch sits where `abort()` or a `ValidationException`
could be swallowed. The snapshot database is per-process with an age-gated sweep
(decisions 121 and 131), and the test fixtures are pid-plus-random scoped. Every
cache payload is scalars or arrays of scalars, rehydrated on read (invariant P5).
The seeder anchors to a fixed day, and its one `now()` writes a column keyed
under `firstOrNew`, so idempotency holds (invariants P2 and P3).

   `app/Services/` or the migrations. The candidate pass is cheap; a clean run
   costs little.

## Process notes

- The candidate pass found a bug in itself: `git grep` patterns beginning with
  `->` were silently parsed as command options, five patterns zeroing six checks
  (one seed serves both B1 and B2). Caught by
  re-verifying suspicious zero-candidate checks against known call sites
  (`$request->query(` exists, so a zero was impossible), fixed with `-e`. The
  skill's failure-modes section records the lesson: a zero from a tool is a
  claim to verify, not a fact.
- This report is itself inside the audit surface of `readlog:docs-check`, so it
  contains no em dashes, cites findings as plain `path:line` code spans rather
  than fragment links, and was verified against the gate before being reported
  as done.
